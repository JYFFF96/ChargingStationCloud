# V1.0-RC1 联调检查表

本检查表用于 Windows 11 + Python 3.11 + 微信开发者工具环境。

## 1. 启动服务端

```bash
cd /d/Code/ChargingStationCloud
source .venv/Scripts/activate
python server/main.py
```

预期：

- TCP `0.0.0.0:8768` 监听成功
- HTTP `0.0.0.0:8000` 启动成功
- Web `http://127.0.0.1:8000/` 可打开
- Swagger `http://127.0.0.1:8000/docs` 可打开

## 2. 启动模拟桩

```bash
python tools/pile_simulator.py --host 127.0.0.1 --port 8768 --pile 32010200000001
```

检查：

- [ ] 0x01 登录上送
- [ ] 0x02 登录成功应答
- [ ] 0x03 心跳周期上送
- [ ] 0x04 心跳应答
- [ ] 0x13 实时数据可在 Web/小程序查看

## 3. Web 远程启动

Web -> 远程启停充电：

1. 选择在线桩 `32010200000001`
2. 枪号 `01`
3. 点击“下发远程启机 0x34”

预期：

- [ ] 平台日志出现 0x34 下行
- [ ] 模拟桩收到 0x34
- [ ] 模拟桩回复 0x33 成功
- [ ] 后续 0x13 的工作状态为充电中
- [ ] 交易流水号在 0x34/0x33/0x13 中保持一致
- [ ] Web 实时页电压/电流/SOC/电量/金额更新

## 4. Web 远程停止

点击“下发远程停机 0x36”。

预期：

- [ ] 平台日志出现 0x36 下行
- [ ] 模拟桩回复 0x35
- [ ] 模拟桩上送 0x3B
- [ ] 平台回复 0x40
- [ ] 交易状态最终为 completed
- [ ] 设备恢复 idle

> RC1 模拟器的 0x3B 是最小链路测试帧，不代表真实 V1.6 完整交易记录字段。真实桩接入后需保存完整 0x3B HEX 再逐字段校准。

## 5. 桩端启动

```bash
python tools/pile_simulator.py --host 127.0.0.1 --port 8768 --pile 32010200000001 --pile-start
```

预期：

- [ ] 模拟桩上送 0x31
- [ ] 平台回复 0x32
- [ ] 平台生成新的交易流水号
- [ ] 模拟桩进入充电状态并持续上送 0x13

## 6. 微信小程序

微信开发者工具打开：

```text
D:\Code\ChargingStationCloud\miniprogram
```

开发环境勾选“不校验合法域名、web-view（业务域名）、TLS版本以及HTTPS证书”。

检查：

- [ ] 首页显示在线设备
- [ ] 扫码页可识别 `zxkcharge://pile/32010200000001/01`
- [ ] 扫码后可进入充电页
- [ ] 充电页实时数据刷新
- [ ] 启动按钮调用 0x34
- [ ] 停止按钮调用 0x36
- [ ] 我的 -> 充电记录可查看后端交易

## 7. 日志与报文校验

Web -> 日志查询：

- [ ] 可看到上行/下行帧类型、桩号、摘要、原始 HEX
- [ ] 将一帧真实 HEX 粘贴到“报文校验”可校验长度和 CRC

## 8. 计费/支付

RC1 保留项目经理原型中的余额、费率、金额、支付/充值入口。当前状态：

- 计费模型页面已接后端费率展示
- 0x13 已充金额可实时展示
- 真正账户、支付渠道、充值、结算数据库尚未接入
- 0x09/0x0A、0x58/0x57 的完整费率下发流程需要真实桩联调后继续校准

## 9. 真实桩测试时必须保存

首次接 ACP611CN / RXDCP810 时，请保存服务端全部日志，重点保留以下帧完整 HEX：

- 0x01、0x03、0x05、0x09
- 0x13
- 0x31、0x33、0x35
- 0x15、0x17、0x19、0x23、0x25（如直流桩上送）
- 0x3B
- 0x57（如果测试平台主动设置费率）

这些真实报文将作为 V1.0 正式版协议校准依据。
